## 3. 从骨架到成品：修了什么（全部有一手运行时源码依据）

交接包 `skeleton/` 是「未验证参考骨架」，有 3 处会直接导致加载失败或调用失败，另有若干需要按官方规范补齐：

1. **模块格式**：Host 是 ESM `export function apply(ctx)`；Client **必须**是包装态
   `window.__ModuleLoader__.load({id, factory(require){...; return module.exports;}})`，
   裸 `module.exports` 不会被 DSH 自动包装（依据：`dsh-client-modules/lib/client.js` 的
   `loaded without registering "${id}" via __ModuleLoader__.load` 报错）。
2. **`Message` 形状（最关键）**：`GenerateOptions.messages` 必须是
   `{id, role, content:[{type:'text',text}], source}` 对象数组，不能是 `{role, content:string}`；
   且 system 必须走 `GenerateOptions.system` 字段，不能塞进 `messages`
   （依据：`dsh-llm/lib/types/message.d.ts`、`dsh-llm-deepseek/lib/index.js:257-264` 的
   `serializeRequest` 会重复 system、`dsh-llm-pi-ai/lib/index.js:1203` 会把 system 历史消息转成 user）。
   因为 `@deepseek-ai/dsh-llm` 不在 profile 的 `node_modules`，插件不能 import 它，故按 duck typing 手工构造。
3. **`GenerateOptions` 只填 5 个字段**：`provider` / `model` / `system` / `messages` / `signal`；
   不传 `temperature` / `maxTokens` / `reasoningEffort`（HANDOFF §5.3 红线，也避免品牌类型校验问题）。
   失败同时覆盖 `finish` chunk 的 `error`/`aborted` 与 `for await` 抛错两条路径。
4. **`client.js` 注册生命周期**：`ctx.locale.register(NS,{zh,en})` 与
   `ctx.slots.inject('conversation.input.right', ...)` 都包进 `ctx.effect` 并返回 disposer，保证停用即回收。
   `module.exports.inject = ['slots','locale']`，`dsh.client.inject` 只控制激活顺序（两者不是一回事）。
5. **同源校验**：主防线委托 `connection.requestRejection(req)`（非 `undefined` 即拒绝，缺席/抛错 fail-closed），
   另加 `isObviouslyCrossSite(req)` 保守补检（`sec-fetch-site: cross-site` 硬拒、显式非 loopback http(s) `Origin` 拒、
   畸形 Origin fail-closed、loopback/opaque origin 放行），覆盖 ACCEPTANCE 2.5 伪造 Origin，且不误伤 Electron 渲染器。
6. **`req.on('close')` 改为 `res.on('close')`**：Node 的 `IncomingMessage 'close'` 在正常完成时也会触发，
   原写法会在成功响应后误 abort 在途模型调用；改为仅当 `!res.writableEnded` 时 abort。
7. **UI 规范**：`react` 由 shell 模块表注入（`require('react')`），不装重复 React；
   文案走 `ctx.locale.register` + `props.t`（保留 `translate()` 兜底）；样式用 `var(--dsw-alias-*, fallback)` 主题 token，
   `<style>` 作为 React 元素随组件卸载移除；不写死品牌色、不碰 `document.body`、不用 iframe。
8. **显示元数据**：补 `locale/*.json` 的 `meta`、原创 `icon.svg`、`exports`/`files` 全列
   （官方 `host-plugin.md` 的 "Complete this checklist before installation"）。
9. **`apply` 幂等加固**：模块级 `WeakSet` 按 host ctx 去重，避免同一 ctx 二次 `apply` 重复注册；
   effect disposer 里删除条目，保证停用后重新激活可再注册。
10. **`catch (err)` 跨 realm 健壮性**：`err.message` 取值不依赖 `instanceof Error`
    （vm/沙箱或上游抛出的可能是普通对象）。

**关闭了交接稿 §8 的三个开放决策**：
- `GenerateOptions` 精确形状 → 已按 `dsh-llm/lib/types/types.d.ts` 定稿（见上 2、3）。
- `ctx.llm.prepareCall()` 是否必需 → **不需要**，`ctx.llm.stream()` 内部 `adapterStream` 已自动绑定 adapter generation；
  `prepareCall` 是给 HMR 场景防止 adapter capability 错配用的，带外一次性调用用不上。
- `props.useInput` 在槽位里的实际注入形态 → `SessionStandardProps` 由框架自动合并进 session 域槽位组件，
  组件直接读 `props.useInput` / `props.inputActions` / `props.sessionId` / `props.t` 即可，`inject: () => ({})` 合法。

## 6. 已知限制与裁决（写给接手/评审者）

1. **5.7「连续增强两次」与 §3.4 四态表的裁决**：
   `revert` 态**单击 = 还原原文**（满足 §3.4 四态表 + 3.6 + 3.8，这是最高优先级契约）。
   5.7 的「连续增强两次」通过「用户手改草稿 → `contentDiverged` 使还原点失效、状态回 `idle` → 再点触发第二次增强」
   路径满足，此时 `sent = latestDraft.current`（增强版）、`backupRef` 更新为增强版、`appliedRef` 更新为二次增强版。
   交接稿里「revert 态点击直接再增强」的读法在精确读到 §3.4 四态表后被推翻，未采用。
2. **`@` 文件/对话引用**：草稿里的 `@` 引用按纯文本送入模型，不做引用展开（交接稿已知限制，未变）。
3. **后处理固定顺序**：`trim → 去零宽 → 剥围栏/前缀 → 剥首尾各一个包裹引号`。
   因此 `"Enhanced prompt: hi"`（前缀被包在引号内）会得到 `Enhanced prompt: hi`（前缀剥不掉）——
   与 `资料/reference/enhance.mjs` 逐字一致，属既定行为，不是回归。
4. **3.9 / 3.12 的在线部分**：会话切换重置、停用后「按钮消失 + 路由 404 + 无 keydown 监听残留」
   由离线测试用真实代码在 disposer 级验证（Host `effect` disposer 移除路由、Client 卸载移除 `keydown`/abort/样式）；
   **未对线上 profile 执行破坏性的停用/重激活循环**，以免干扰用户正在使用的 GUI。
   组件本身是 `scope:'session'` 槽位，会话切换会自然卸载重挂，state 必然重置。
5. **桌面版 CLI**：`--dump-config` 被 Electron 独占拒绝；安装/卸载/启停一律走
   `plugin_manager`（`install_bundle` / `set_plugin`），不要直接改 profile 的 `package.json` / `cordis.patch.yml`。
6. **浏览器验证的认证前提**：GUI 有 web auth 门控，脚本化验证需复用本机已认证会话；
   提供给他人时应说明「需在已登录 GUI 里手动点一下」或用其自己 `dsh web` 打印的带 token URL。

## 9. 图标与动效升级（v1.1）

**问题**：初版四态图标是文字字形 `✨ ⟳ ↩ ⚠`，字形受系统字体影响、`⟳` 旋转观感生硬。

**方案选择（受硬约束）**：客户端 bundle 运行时只能 `require('react')`，不能 import 任何其他包
（官方 `practices.md` 明令禁止加载其它 Harness Client 包，`dsh.client.external` 也只能指向模块图里的行）。
所以无法 `import { Sparkles } from 'lucide-react'`。采用**把成熟图标库的 SVG path 内联**：
选自 **Lucide**（https://lucide.dev，ISC License），在 `client.js` 里用 `React.createElement('svg', ...)` 渲染，
`stroke: currentColor` 自动继承按钮主题色，零运行时依赖、零额外网络请求。

- 四态映射：idle → `sparkles`（5 路径）、enhancing → `loader` 圆弧、revert → `undo`（回转箭头）、error → `alert`（警告三角）。
- 动效改进：
  - 状态切换时图标 `prompt-enhance-pop`（0.16s，透明度 .35→1 + scale .7→1 回弹）；
  - enhancing 用 0.9s 匀速 SVG 旋转（`transform-box: fill-box` 保证绕中心）；
  - 按钮 `color/background-color` 0.15s 过渡，hover 用 `--dsw-alias-link-normal`；
  - `@media (prefers-reduced-motion: reduce)` 下全部动画关闭，尊重系统设置。
- 无障碍与稳定定位：按钮新增 `data-state` 属性（离线测试与自动化据此断言，不再依赖字形文本）；
  `aria-label`/`aria-busy`/`title` 语义不变。
- 附带修一处状态机细节：**失败后手改草稿会解除 ⚠ 回到 idle**（错误属于触发它的那段文本；
  之前 error 态会对新草稿粘住）。新增离线用例 `3.10c` 覆盖。

在线复核（真实 GUI，同一已认证会话）：四态均渲染 `<svg class="dsh-pe-icon">`，enhancing 时 class 追加 `dsh-pe-spin`，
`stroke="currentColor"`，sparkles 有 5 条 `path`。预览见 `产出/四态图标预览.png`。
离线复核：Host 41 + Client 29（新增 1 项）+ demo 13 = **83 项全通过**。
