①

Host 半 · 服务端

Node / ESM · 注册本机路由、守同源闸门、调一次 LLM、清洗并回 envelope
1入口与生命周期B

export const name + export function apply(ctx)

所有注册都放进 ctx.effect() 并返回 disposer —— 插件卸载时全部可逆。

2注入本机路由B

ctx.inject(['webServer'], install) → 在 ctx.effect() 内注册：

webServer.register({kind:'prefix', path:'/prompt-enhance', handler})

纯前缀路由，只挂在本机 DSH 的 Web 服务上。

3同源闸门 · fail-closedA

ctx.get('connection').requestRejection(req) → 返回值 非 undefined 即 403（fail-closed）。

另校验 loopback host + sec-fetch-site + Origin。

403 forbidden · 跨站 405 method_not_allowed · 非 POST 400 bad_request · 坏 JSON

4HTTP 契约A

POST /prompt-enhance/enhance · body {text, model?}

恒返回 HTTP 200 envelope —— 业务成败放在 body 的 success 里，不用 HTTP 状态码表达。

5选模型B

ctx.agentDefaultModel.currentSelection() → {provider, model, reasoningEffort?}

请求体里的 model? 可覆盖；只走本机 DSH 模型路由。

reasoningEffort? 是否随调用透传仍C待定。

6单次 LLM 调用B

ctx.llm.stream(options) —— 单次尝试。

不受 dsh-llm-retry 覆盖：它只包裹 agent-loop 的步骤，这里绕过整个 agent loop。

messages = 恰好 system + user；NO tools / NO history / NO temperature / NO maxTokens。

7聚合与清洗A

聚合 text-delta 分片；检查 finish.reason.kind ∈ {error, aborted}。

trim→ 去零宽字符→ 剥代码围栏 / “Enhanced prompt:” 前缀→ 剥首尾各一个中英包裹引号→ 空则 llm_error

cleanEnhanced 全是软规则：LLM 输出没有固定小标题可依赖。

8返回 envelopeA
{success:true, text} {success:false, text:'', code, error}

错误码：

单次请求 / 响应 · 同源回环

① 请求POST /prompt-enhance/enhance
body {text, model?}

ctx.locale.register(NS, {zh, en}) —— 按钮文案与失败原因走统一命名空间。

4与草稿交互A

Shell 传入 props：useInput(s => s.draft) + inputActions.setDraft(text)

整段草稿替换，NEVER 自动发送。

setDraft 是 Lexical history-merge 编辑 → 原生 Cmd+Z 回不到增强前文本 → 精确拦截一次 Cmd/Ctrl+Z。

6铁律 · 写回与生命周期A

失败绝不写回草稿；调用期间草稿被改动 → 放弃写回；成功后 草稿 !== enhanced → 还原点失效。

切换会话重置 · 卸载 abort · 不做流式回填 · 不弹 toast。

▣ 硬边界 · 一次调用能做什么只在本机闭环

✓ 允许 只经过本机 DSH 模型路由
✕ 禁止 不访问任何外部服务 / WorkBuddy 不进 agent loop 不注册工具 不写会话日志 不自动发送 不做流式回填

两半的所有注册都经 ctx.effect() disposer 可逆；整条链路不依赖 CDN、外部服务或插件外状态。

5 14 条坑 · 最关键的 5 条小字注释

  1. 1
    $& 函数式替换A

    替换串里的 $& 会被展开成"整个匹配"；用 () => text 函数式替换，别拼字符串。

  2. 2
    原生撤销失效A

    setDraft 是 Lexical history-merge 编辑，Cmd+Z 回不到增强前；必须精确拦截一次 Cmd/Ctrl+Z。

  3. 3
    内联 @引用 chip 会丢A

    整段 setDraft 覆盖草稿会丢掉内联 @ 引用 chip（富文本节点），不是纯文本能还原的。

  4. 4
    无固定小标题BC

    LLM 输出没有稳定的小标题格式，cleanEnhanced 只能靠前缀 / 围栏 / 引号做软规则；多重引号等边界仍待定。

  5. 5
    失败不覆盖草稿A

    success:false、调用中草稿被改动、成功后 草稿 !== enhanced —— 三种情况都放弃写回。
